# 附录：扩展认证（Alpha）

> 本文是 [RFC](../README.md) 的附录。阅读前请先熟悉 RFC 正文。

RFC 正文将认证传输机制留作后续协议工作：它要求机密性，并对目标中间件服务进行认证；描述了第一阶段的 `allow_insecure` 逃生通道；并将第二阶段在 mTLS、TLS 加显式调用方认证或等效方案之间的选择推迟。本附录记录 alpha 阶段实际构建的机制。它取代正文中关于传输认证和 `allow_insecure` 的段落；正文其余部分不变。

相关：[protocol-extensions.md](protocol-extensions.md#middleware-authentication)。

## Alpha 阶段交付内容

传输使用 HTTPS，信任根为平台信任根或运维方提供的 CA 包，并执行常规的证书和端点主机名验证。中间件端点必须能从每个沙箱 supervisor 以及网关访问，因此网关本地 Unix socket 不适用于此机制。

调用方身份是由网关现有沙箱签名机构签发的短期 Ed25519 JWT。网关在自身的 `Describe` 和 `ValidateConfig` 调用中附带一个；沙箱 supervisor 在 `Describe` 和 `EvaluateHttpRequest` 中附带一个。RFC 所述要求的两个方向均已覆盖：TLS 和配置的信任根向 OpenShell 认证中间件服务，精确受众的 JWT 向中间件证明调用来自网关或策略授权的沙箱 supervisor。

## 声明契约

| 声明 | 含义 |
|---|---|
| `iss` | 精确为 `openshell-gateway:<gateway_id>`。 |
| `aud` | 单个注册的精确受众。绝不为列表。 |
| `sub` | 网关调用方为网关身份；supervisor 调用方为 `spiffe://openshell/sandbox/<id>`。 |
| `caller_kind` | `gateway` 或 `supervisor`。 |
| `sandbox_id` | 仅 supervisor 调用方存在。 |
| `jti` | 每个令牌唯一。OpenShell 不跟踪。 |
| `iat`、`exp` | 有界生命周期，最长一小时。 |

JOSE 头携带 `alg: EdDSA`、签名 `kid` 和 `typ: openshell-ext+jwt`。

显式类型存在的原因是：扩展令牌和沙箱到网关的准入令牌由同一密钥签名，否则仅靠受众区分。要求此 `typ` 的验证方即使忽略检查 `aud`，也无法接受沙箱引导凭证。这是针对最可能的验证方错误的纵深防御，而非受众验证的替代。

## 授权与分发

Supervisor 通过现有 `RefreshSandboxToken` RPC 按运维注册名请求凭证，该 RPC 已认证沙箱主体。网关在签发前，将每个请求名对照服务器拥有的注册元数据和沙箱的有效策略进行解析；未知、未选中或重复的名称被拒绝。调用方从不选择受众。

由于该解析运行完整的有效策略组合，适用两个限制。Supervisor 仅在凭证缺失或已过其生命周期五分之四时轮换，而非每次配置轮询时轮换；网关限制单个沙箱每分钟的签发请求数。

## 受众约定

受众在 OpenShell 侧是运维配置，在中间件侧是服务配置。严格验证方在分发 `Describe` 前拒绝不匹配的令牌，因此 OpenShell 可能只观察到认证失败。

服务可在其 `Describe` 清单的 `expected_audience` 字段中声明其验证的受众。认证 `Describe` 成功后，OpenShell 将该值与配置值比较，不匹配则拒绝注册。这是认证后的一致性断言，而非受众发现。空字段表示服务不声明受众，检查跳过，因此对现有服务是增量的。

## 验证密钥分发

运维方提供的公钥或 JWKS 是权威的冷启动信任锚。通过用于网关 URL、预期网关 ID 和私有 CA 的同一可信配置路径，将其与扩展服务一同部署。这使服务能在首次认证调用时验证，而无需信任从该调用对端学到的密钥材料。

网关还在 `/.well-known/jwks.json` 发布其公共签名密钥为单密钥 JWKS，并在 `/.well-known/openid-configuration` 发布 OIDC 形状的发现元数据，携带预期 `iss`、绝对 `jwks_uri` 和 `EdDSA` 作为唯一支持的算法。初始信任建立后，扩展可使用这些端点进行稳态密钥刷新和运维便利。

发现文档是 OIDC 形状而非 OIDC 合规，方式与原因同等效的 Kubernetes 端点：`issuer` 是网关身份，而非文档服务所在的 URL。验证方将 `iss` 与该值比较。获取文档不建立网关身份；预配置的网关身份和认证的 TLS 连接才建立。因此，well-known 端点不是运维方提供的首次接触信任的替代。

## 兼容性

注册可设置 `allow_insecure_transport = true`，以更清晰的名称和更广的含义取代正文的 `allow_insecure` 字段：它使注册完全退出扩展认证。OpenShell 不附带凭证，supervisor 不请求凭证，网关在被请求时拒绝签发，且每次网关启动时记录一条命名该注册的警告。

这使明文注册继续适用于受信任的本地开发和隔离研究环境，并保持扩展认证存在前配置的部署的兼容性。正文关于此为临时、可审计、显著警告的逃生通道的意图得以保留。

## 残余风险

- **令牌生命周期内的持有者重放。** 任何获得令牌者可在过期前使用。短有界生命周期限制窗口。`jti` 标识令牌实例用于关联或未来显式撤销，但 OpenShell 跨调用重用令牌，不跟踪或撤销。每请求重放抵抗需要请求绑定或持有证明。
- **两个信任域共享签名密钥。** 扩展凭证和沙箱准入凭证来自一个密钥和一个 `kid`。它们由受众和 `typ` 分离，但扩展令牌签发无法独立于沙箱准入轮换或撤销。单独的扩展签名密钥是自然的下一步，基于 `kid` 的设计不排除它。
- **单密钥 JWKS。** 无重叠窗口，因此密钥轮换尚非零停机操作。
- **无通道绑定。** mTLS 或其他持有证明机制仍为推迟的加固。

## 推迟项

mTLS 客户端认证、带重叠窗口的多密钥轮换、超出短期过期的重放抵抗，以及每运行时密钥交付，均不在 alpha 范围内，仍为后续工作。
