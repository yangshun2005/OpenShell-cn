# RFC 0014 补充 - 发布资格

预发布版本只有在其构建产物通过所有必需的[一致性测试](#一致性测试)和[升级测试](#升级测试)、[破坏性 API 变更审查](#破坏性-api-变更审查)以及[安全审查](#安全审查)后，才有资格正式发布。

## 一致性测试

一致性测试针对不同的 OpenShell 驱动、网关和主机配置运行。每个工作流在一个代表性环境中安装预发布版本，并验证该配置下支持的 OpenShell 行为。

对每个驱动，测试套件执行：

1. 安装预发布构建产物，启动网关和选定的运行时。
2. 验证网关健康状态、版本报告、TLS、认证和授权。
3. 创建沙箱、连接沙箱、执行命令，并在支持的情况下测试停止、重启和恢复行为。
4. 测试文件系统、进程、网络、凭据和推理策略的执行，包括预期的拒绝行为。
5. 验证配置的计算驱动、凭据驱动、拦截器和中间件契约，包括能力发现、校验、错误处理、重启协调和清理。
6. 删除沙箱，确认运行时、网络、凭据和持久化资源已被清除。

只有当每个驱动工作流完成且没有未声明的跳过或依赖重试的结果时，一致性测试才算通过。当某配置不支持被测能力时，可以选择退出特定一致性测试。退出声明和不支持的能力必须在资格测试运行前在测试配置中声明；其他任何跳过都会导致资格测试失败。一个工作流可以在不创建额外工作流的情况下，以子用例形式测试相关的 GPU、认证、凭据驱动、拦截器、中间件和客户端/服务端版本偏差变体。不支持的能力必须返回文档化的错误，而非静默失败。

每个工作流为被测配置使用一个代表性环境。可以在该环境内运行多个能力子用例，无需创建额外工作流。

## 升级测试

升级测试对每个受支持的产品安装包运行一次。验证用户可以从每个受支持的源版本迁移到预发布版本，无需重新安装或丢失受支持的状态。

对每个安装包，测试套件执行：

1. 安装源版本，创建代表性网关、沙箱、策略、提供者、凭据和持久化状态。
2. 运行源版本安装以建立已知良好的基线。
3. 使用预发布构建产物执行文档化的原地升级。
4. 验证 Schema 和状态迁移、网关健康状态、现有资源、策略行为和新沙箱创建。
5. 运行升级后冒烟测试，验证现有资源并创建和删除新沙箱。
6. 当回滚属于受支持的升级契约时，测试回滚。

## 破坏性 API 变更审查

破坏性 API 变更审查对每个预发布版本运行一次。将其稳定 protobuf 和公共 SDK 接口与最新稳定基线以及 N-1 维护承诺所需的任何附加基线进行比较。审查内容：

1. 针对受支持的描述符基线运行 protobuf 兼容性检查。
2. 对生成和手写的 SDK 或配置接口运行语言特定的兼容性检查。代理可以使用破坏性 API 检测技能来评估。

当没有未处理的破坏性变更影响稳定 API 基线，且每个有意的次要版本破坏都满足版本控制和迁移要求时，破坏性 API 变更审查通过。

## 安全审查

安全审查对每个预发布版本运行一次，将：

1. 生成预发布构建产物的漏洞、依赖、容器和基础设施扫描结果。
2. 对自上一稳定版本以来的变更运行基于代理的安全扫描器，如 Codex Security。

当没有未解决的严重或高危发现影响受支持的配置时，安全审查通过。
