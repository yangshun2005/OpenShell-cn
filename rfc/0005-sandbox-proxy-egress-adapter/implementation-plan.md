# 实施计划

本计划有意与主 RFC 分离，以便提案保持方向聚焦。RFC 是增量路线图，不是单个 Pull Request。阶段 0 到 7 构成兼容性基础：它们重构现有的 CONNECT、转发 HTTP、原始 TCP 和本地服务行为，不新增面向用户的传输方式。阶段 8 及之后在共享契约成为权威后添加前瞻性能力。

## 阶段 0 - 兼容性基线

- 覆盖 CONNECT 和转发 HTTP 的允许/拒绝响应，包括确切状态码、头部和适配器特定的错误响应体。
- 覆盖转发 HTTP 流水线、keep-alive 后续请求、当前的 `Connection: close` 缓解措施、`https://` 绝对形式拒绝，以及被检查端点上的 h2c 拒绝。
- 分别覆盖当前重叠策略在匹配策略、L7 路由选择、TLS、`allowed_ips` 和精确声明主机方面的结果。
- 向 L7、TLS、`allowed_ips` 和精确声明主机查询注入故障。记录每个查询当前的 fail-open 或 fail-closed 结果，而不是将所有端点元数据错误视为等价。
- 覆盖控制平面端口、云元数据、始终阻止的地址、精确声明的私有端点、IP 字面量合成、受信任网关别名，以及通过 CONNECT 和转发 HTTP 的显式 `allowed_ips`。
- 覆盖需要身份时的成功/失败、尽可能覆盖不支持平台的行为，以及有意的仅端点评估。证明在需要身份时，空的 `exec.path` 无法满足二进制作用域策略。
- 覆盖静态凭据注入、令牌授予、REST 请求体重写、WebSocket 文本帧重写与策略、GraphQL、JSON-RPC 和 MCP 行为。
- 覆盖 `policy.local`、元数据回环，以及未更改的 nftables 绕过拒绝/日志行为。
- 为代表性允许和拒绝路径捕获稳定的 OCSF 事件类、活动/动作/处置、严重性、状态、目标、行为者、防火墙规则、消息和状态详情。
- 记录 OPA 评估、每连接分配和 CONNECT/转发请求延迟的性能基线。

## 阶段 1 - 适配器与兼容性决策信封

- 在 `openshell-supervisor-network` 内引入 CONNECT 和转发 HTTP 的 `EgressIntent` 构造。
- 引入过渡性的 `EgressDecision`，携带 L4 结果、策略代次、进程证据和端点字段，同时保留当前的查询时机、优先级和失败默认值。
- 在需要身份时，将 `LookupFailed`/不支持的身份保持为拒绝。保持显式配置的仅端点模式行为不变。
- 将适配器特定的响应和 OCSF 发射保留在协议边界。
- 不要声称过渡性决策是单个原子 OPA 结果；记录其兼容性水合，直到阶段 3 切换。

本阶段是机械性提取。它必须可独立发布和回滚，不改变用户可见的策略或中继行为。

## 阶段 2 - 共享目标验证

- 将 DNS 解析、显式 `allowed_ips`、精确声明的端点、隐式 IP 字面量处理、受信任网关别名、SSRF 检查、云元数据阻止和控制平面端口阻止移入一个验证器。
- 显式表示选定的验证模式，而不是传递一组含义模糊的布尔值。
- 返回未打开的 `UpstreamConnector`，以便适配器和中继保留当前创建上游 TCP 的时点。
- 证明 CONNECT 和转发 HTTP 在使用共享验证器时保留现有的拒绝响应、OCSF 字段和拨号时机。

## 阶段 3 - 代次一致的授权切换

- 在更改执行之前，定义对模糊重叠端点元数据的拒绝，或定义一个文档化的策略/端点优先级键。
- 添加一个 OPA 结果，从单个策略代次物化匹配的策略/来源、匹配的端点、目标约束、TLS、HTTP 执行、凭据计划和中间件选择。
- 将代次固定的 `TunnelPolicyEngine` 附加到中继上下文，用于每请求的 REST、GraphQL、JSON-RPC、MCP 和 WebSocket 评估。中继不重新物化连接级端点策略。
- 在旧查询旁边以影子模式运行新查询。发出内部、审计安全的失配遥测，不改变现有 OCSF 网络/HTTP 事件或执行。
- 添加重载竞态测试，证明每个物化字段与顶层代次匹配，且过期决策在上游请求写入前停止。
- 在理解失配情况后，将确定性选择和 fail-closed 的 L7/TLS 元数据错误作为专用切换。暂时保留旧评估器以便立即回滚。

这是唯一有意收紧模糊或错误行为的阶段；它不得隐藏在结构性重构提交中。

## 阶段 4 - 转发 HTTP 适配器

- 将绝对形式解析和适配器特定错误保留在转发 HTTP 边界。
- 将缓冲的首个请求传入共享 HTTP 中继，或保留受保护的单请求/`Connection: close` 路径，直到阶段 5a 就绪。
- 保留 `https://` 绝对形式拒绝和被检查的 h2c 拒绝。
- 保留不变式：未经评估的后续请求不能到达原始双向复制。

## 阶段 5 - 中继整合

### 阶段 5a - HTTP 请求循环

- 将 HTTP 解析和每请求的 REST、GraphQL、JSON-RPC 和 MCP 评估集中到代次固定的请求策略句柄之后。
- 在上游写入前评估每个请求，并保留当前规则：被拒绝的请求不创建上游会话。
- 保留有界 JSON-RPC/MCP 检查和省略参数与工具参数的审计安全日志。

### 阶段 5b - 凭据注入

- 在请求允许后、上游写入前，统一静态目标/查询/头部重写、端点绑定的令牌授予和可选的 REST 请求体重写。
- 保留缓冲限制、支持的内容类型、`Content-Length` 重新计算、脱敏、令牌缓存和 fail-closed 的未解析密钥。

### 阶段 5c - WebSocket

- 将允许的升级移到共享中继之后，同时保留原始升级透传、可选的文本帧凭据重写、WebSocket 传输策略、GraphQL-over-WebSocket 策略和安全压缩行为。

### 阶段 5d - Supervisor 中间件

- 仅在 supervisor 中间件依赖可用后落地。
- 在请求允许后、静态或动态凭据注入前运行 `HTTP_REQUEST / PRE_CREDENTIALS`。
- 重新解析中间件转换后的请求体，并在凭据注入或上游写入前重新评估 GraphQL、JSON-RPC 和 MCP 策略输入。保留端点的审计或执行行为以处理策略失配，并在任一模式下对格式错误的转换后协议体 fail closed。
- 保留顺序、请求体上限、`fail_open`/`fail_closed`、安全头部、发现项、元数据，以及拒绝中间件引入的凭据占位符。
- 测试被中间件重写为拒绝的 GraphQL、JSON-RPC 和 MCP 操作的允许请求，包括审计模式转发和 fail-closed 的格式错误替换。

每个子阶段必须可独立测试和发布；阶段 5 不是单次切换。

## 阶段 6 - 共享 TLS 和 TCP 中继边界

- 将客户端 TLS 检测和终止移到 HTTP/原始 TCP 中继拆分之前，不改变握手、证书或上游连接时机。
- 将端点 TLS 行为保留在 `EgressDecision` 上，并保留 `tls: skip` 作为显式原始隧道路径。
- 对 L4 流量使用一个现有的原始 `TcpRelay` 字节复制原语。
- 添加协议处理器分派契约，但在兼容性里程碑中不启用具体的新协议。
- 让处理器拥有自己的消息循环，仅在协议状态允许时调用已验证的连接器。允许树内、中间件支撑和混合处理器，支持类型化中间件操作。

## 阶段 7 - 现有本地服务与清理

- 将 `policy.local` 保留为当前策略、有界拒绝摘要、提案和提案等待的本地适配器。
- 决定元数据回环仍由 `openshell-sandbox` 编排，还是移到本地适配器边界之后；无论哪种方式都保留启动/失败行为。
- 保持本地路由和目标契约可扩展以支持 Issue [#1633](https://github.com/NVIDIA/OpenShell/issues/1633)，同时将其策略面和主机回环授权留给单独的功能工作。
- 仅在阶段 3 成为权威后移除兼容性端点查询。
- 移除重复的目标/中继管道，但不集中化适配器特定的响应渲染。
- 在每个已实施的边界反映当前代码后，更新活架构文档。

阶段 7 的完成是兼容性里程碑：现有面向用户的功能和能力在新内部结构上得到保留。后续阶段是功能承载工作，在单独的 Pull Request 或系列中落地。

## 阶段 8 - 策略 DNS 和透明 TCP

- 为原生 TCP 端点名称添加策略 DNS 注册。
- 在发起上游 DNS 查询前，拒绝不匹配合格原生 TCP 端点的名称。
- 用查询驱动的合成 DNS 应答替换静态 hosts 文件映射。通过受信任 DNS 解析合格名称，并通过目标控制过滤每个真实地址。
- 分配 supervisor 拥有的合成 IP，并在活动映射状态中存储规范化名称、端点 ID、允许端口、已验证的真实地址、策略代次、独立的 DNS 映射代次、映射 ID 和过期时间。
- 要求每个捕获的连接与其合成目标和请求端口所选的未过期映射关联。不允许无关的裸 IP 流量继承策略 DNS 决策。
- 在返回合成 DNS 应答前，从适配器视角原子地发布映射和 nftables 捕获更新。
- 在绕过拒绝路径之前添加 nftables REDIRECT/TPROXY 捕获规则；不添加并行的 iptables 路径。
- 与 `openshell-supervisor-process::netns` 协调捕获规则所有权，并为未匹配流量保留拒绝/日志回退。
- 恢复原始目标，构造透明 TCP 意图，并运行正常的代次一致授权和目标验证。
- 将连接器限制为映射固定的已验证真实地址；不在连接时独立重新解析。
- 保持直接外部 DNS 被阻止，并将 DNS-over-HTTPS 视为普通策略控制的 HTTPS 出口。
- 在默认启用捕获前，定义合成地址池并复用隔离、TTL 上限、策略重载失效、过期映射行为和回滚。

## 阶段 9 - 原生协议处理器

- 一次添加一个具体的 Redis、Postgres、MySQL 或其他处理器，每个都有单独审查的策略 Schema 和操作限制。
- 将省略/`tcp` 端点保持在原始 L4 字节复制；绝不从流量本身推断原生处理器。
- 测试多消息会话、预拨号拒绝、需要握手的拨号、每命令/查询评估、中间件 Hook、超时和脱敏。
- 对指定运行代理构建中不可用处理器的策略进行能力门控。

## 阶段 10 - 运行时边界

- 将嵌入式和仅网络 supervisor 模式保留为迁移基线。
- 定义未来独立二进制或 sidecar 所需的代理运行时 API：配置的监听器、策略更新、提供者凭据、令牌授予、中间件注册表、网关调用、遥测、拒绝/活动事件和关闭。
- 通告进程身份和协议处理器能力。拒绝需要不可用二进制/路径身份或处理器支持的策略。
- 将有意运行时身份不可用与现有仅端点模式和查找失败分开表示。
- 如果代理和网关版本可能不同，添加网关能力协商。

## 阶段 11 - 最终清理

- 在观察窗口关闭后，移除为确定性决策回滚保留的任何兼容性查询/评估器。
- 随着相应后续阶段落地，从代理设计和架构文档中移除过时的静态 `/etc/hosts`、iptables 或单进程假设。
- 将适配器特定的响应渲染和 OCSF 契约保留在协议边界。

## 测试与操作验证

- 单元测试适配器意图构造、响应渲染、显式目标模式、身份证据和授权优先级。
- 集成测试跨 CONNECT 和转发 HTTP 的目标验证，然后在阶段 8 落地时对透明 TCP 复用同一套件。
- 集成测试 HTTP keep-alive/流水线、REST、GraphQL、JSON-RPC、MCP、WebSocket、凭据、令牌授予、中间件和 TLS/原始 TCP 选择。
- 集成测试 `policy.local` 和元数据回环的请求体限制、超时、脱敏和本地拒绝响应。
- 在每个迁移子阶段前后比较 OCSF 夹具。
- 在 L4 决策、端点物化、中继启动和长期每请求评估之间演练策略重载。
- 在添加 Redis、Postgres、MySQL 或类似执行前添加协议处理器测试框架。每个具体处理器添加多消息、握手、超时、拒绝、脱敏和中间件覆盖。
- 集成测试策略 DNS 过滤、无上游查询的拒绝、合成应答分配、TTL 和复用隔离、独立映射代次、策略重载失效、原子捕获规则更新、原始目标恢复、允许端口关联、连接器限制为固定真实地址，以及拒绝无关裸 IP 连接。
- 证明解析到相同真实 IP 和端口的两个名称获得不同的关联，且不能继承彼此的端点策略。
- 测试独立/sidecar 能力协商，并证明缺失身份或处理器支持在策略验证期间失败，而不是在运行时扩大允许。
- 在兼容性信封后、单决策查询后和中继整合后重新运行性能基线。将减少的 OPA 调用视为测量结果而非假设收益。
- 通过回滚其隔离提交来退出结构性阶段。在确定性切换观察窗口期间保持影子比较和旧评估器可用。
- 独立门控后续传输/运行时阶段，以便禁用策略 DNS 或透明捕获时恢复现有的显式代理和绕过拒绝行为，而不回滚兼容性基础。
