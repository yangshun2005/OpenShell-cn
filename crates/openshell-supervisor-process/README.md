# OpenShell 进程监督器

本 crate 通过已准入的隔离后端管理工作负载进程和 SSH 会话。

## 有界流式上传

CLI 内置上传使用 `openshell-upload-v1` SSH 子系统。Russh 在监督器消费通道数据之前就返回 SSH 接收信用，因此该子系统返回自己的信用，其余全部走 SSH。网关转发通道但不解析其内容。

客户端先发送一行 JSON 计划（含目标路径），再发送原始 tar 流，最后发送 SSH EOF。计划到达后，监督器通过常规 `BoundaryExec` 路径启动解压器，其工作负载身份、环境、工作目录和文件系统策略与其他 SSH 子进程相同。启动内联执行，与 exec 请求一致。

stdout 只携带大端 `u64` 累计值，表示 `InputTask` 已通过 `BoundaryInput::write_all` 写入的归档字节数。首个累计值为零，表示解压已开始。解压器的 stdout 和 stderr 都作为 SSH stderr 发送，因此解压器输出无法伪造信用。客户端最多只能在最后一个累计值之外保留 1 MiB 未确认数据；监督器拒绝超出该窗口的输入。现有 4 MiB 待处理输入保护仍然生效。

解压器成功退出且 stdin 排空后，监督器发送最终累计值，然后发送退出状态。仅当状态为零且最终累计值等于客户端发送的字节数时，客户端才成功。计划格式错误、信用违规、扩展数据或计划之前出现 EOF，都会使上传失败，退出状态为 74。在监督器报告退出结果之前，拒绝始终优先，即使解压器已退出。拒绝、通道关闭或断开连接都会终止解压器。解压直接写入目标路径，因此失败可能留下部分解压的文件；没有回滚或原子替换。

CLI 在发送归档数据前要求监督器支持该子系统。它不会回退到之前无节流的 exec-stdin 上传路径。普通 exec stdin 和 SFTP 保持现有的输入预算行为。
